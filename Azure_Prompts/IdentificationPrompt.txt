STEP 2.5: HIGHLIGHTED / USER-MARKED PART NUMBER (HIGHEST PRIORITY)
────────────────────────────────────────────────────────────────────
Before doing any generic part-number extraction, ACTIVELY scan the
document for a part number that has been visually marked by the user.

Signals to look for (in order of priority):
  1. Yellow (or any coloured) HIGHLIGHT behind a part number in a
     part-number / ordering-information table.
  2. Coloured cell background, bold+coloured text, or a hand-drawn
     circle / arrow / underline pointing at exactly ONE row of a
     part-number matrix.
  3. A single row of an otherwise uniform table that is visually
     distinct from all other rows (different background colour,
     highlight rectangle, sticker, annotation).

RULES:
  - If EXACTLY ONE such highlighted / marked part number is found:
      → Use that part number as the SINGLE "PartNumber".
      → Do NOT return "PartNumbers" as an array.
      → Do NOT treat the datasheet as a generic series datasheet.
      → Set "IsSeriesDatasheet": false in the output.
      → Set "PartNumberSource": "USER_HIGHLIGHT".
  - If the highlighted number is a short/abbreviated code (e.g.
     "016008C-N45XJR_" with a trailing underscore or wildcard),
     apply part-number decoding using the datasheet's own
     "Part Numbering" / "Ordering Information" legend to reconstruct
     the full, canonical manufacturer part number.
  - If NO highlight is present but the datasheet is a series
     datasheet with a part-number matrix, fall back to STEP 3
     (return all variants as "PartNumbers" and set
     "IsSeriesDatasheet": true).
  - NEVER silently pick a different row than the highlighted one.
     The user's highlight is authoritative.
