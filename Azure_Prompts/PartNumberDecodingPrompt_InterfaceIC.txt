?? CRITICAL RULES FOR INTERFACE IC DECODING
???????????????????????????????????????????????????????????????????????????????

1?? **Funktion Property** (MUST match dropdown options!):
   Map interface type to these EXACT values:
   • "Interface Controller" (if IC manages/coordinates protocol)
   • "Interface Controller" (alternative for controllers)
   • "Driver , Receiver , Transceiver" (if IC converts signals bidirectionally)
   • "Switch , Mux , Demultiplexer" (if IC routes/selects signals)
   • "Signal Buffer , Repeater , Splitter" (if IC amplifies/distributes)
   • "Serializer , Deserializer" (if IC converts parallel ? serial)
   • "Coder , Decoder ( CODEC )" (if IC encodes/decodes data)
   • "I/O Expander" (if IC adds more I/O pins)
   • "Bridge" (if IC connects different buses/protocols)

   **DECISION ALGORITHM:**
   ```
   IF part number indicates "Controller" or "Manager":
       Funktion = "Interface Controller"
   
   ELSE IF part number indicates "Transceiver" or "Driver+Receiver":
       Funktion = "Driver , Receiver , Transceiver"
   
   ELSE IF part number indicates "Driver" only:
       Funktion = "Driver , Receiver , Transceiver"  // Still use full option
   
   ELSE IF part number indicates "Receiver" only:
       Funktion = "Driver , Receiver , Transceiver"  // Still use full option
   
   ELSE IF part number indicates "Multiplexer" or "Switch":
       Funktion = "Switch , Mux , Demultiplexer"
   
   ELSE IF part number indicates "Buffer" or "Repeater":
       Funktion = "Signal Buffer , Repeater , Splitter"
   
   ELSE IF part number indicates "SerDes" or "Serializer":
       Funktion = "Serializer , Deserializer"
   
   ELSE IF part number indicates "CODEC" or "Encoder":
       Funktion = "Coder , Decoder ( CODEC )"
   
   ELSE IF part number indicates "Expander" or "Extender":
       Funktion = "I/O Expander"
   
   ELSE IF part number indicates "Bridge" or "Translator":
       Funktion = "Bridge"
   
   ELSE:
       Funktion = "nicht vorhanden"  // Unable to classify
   ```

2?? **Interface Detection**:
   • **Interface_internal**: What the IC talks to on the HOST side (MCU/CPU interface)
     - Common: UART, SPI, I2C, USB, PCIe, LVDS
   
   • **Interface_external**: What the IC talks to on the BUS side (physical layer)
     - Common: RS-232, RS-485, CAN, LIN, Ethernet, USB, HDMI
   
   **EXAMPLES:**
   - MAX3232 (UART-to-RS232): Internal=UART, External=RS-232
   - MCP2515 (SPI-to-CAN): Internal=SPI, External=CAN
   - FT232 (USB-to-UART): Internal=USB, External=UART
   - CH340 (USB-to-UART): Internal=USB, External=UART

3?? **Package & Pitch & NumberOfPin** (CRITICAL — fill these even when chart is sparse!):

**EXTRACTION ORDER (try every step!):**
1. Read package code segment from part number ? look up Meaning + PinCount in chart
2. If chart has no PinCount ? infer from package suffix (e.g. `-16`, `SO16`, `TSSOP-16` ? 16)
3. If still unknown ? search the datasheet text for "Pin Configuration", "Pinout",
   "Package Information", "Mechanical Drawing", "Outline Dimensions"
4. If images/drawings are provided ? COUNT THE PINS in the package outline view!

**NumberOfPin MUST be a plain integer string** (e.g. "16", "20", "8"). Never "nicht vorhanden"
if the package code in the part number identifies a known SO/TSSOP/SSOP/QFN/DIP package!

**Pitch — ALWAYS provide a value when PackageType is known. Use this lookup table:**
